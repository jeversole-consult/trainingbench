# Training-Set Strategy — TB-US-075 Phase 4

**Owned by**: TB-US-075
**Created**: 2026-10-31
**Companion to**: [`study-design.md`](study-design.md) (full pre-registration),
  [`baseline-analysis.md`](baseline-analysis.md) (Phase 3 failure analysis)

Composition decision + rationale for the training set that targets
the specific baseline failures identified in Phase 3.

## Composition decision: Option A (minimal)

**Chose**: Option A from the study-design — the training set is
**exactly the 200 baseline failures, paired with their GSM8K
chain-of-thought ground-truth answers**. No augmentation, no
scale-up with additional train-split problems.

**File**: `training-sets/math-example-v2-failures.jsonl` (200 rows,
each with `sample_id` + `question` + full-CoT `answer` ending in
`#### N`)

**Generated by**: `scripts/prep_math_failures_jsonl.py` —
deterministic, reproducible from the committed experiment data.

### Why Option A, not B or C

**Option B (scale-up with extra train-split problems)**:
- Larger training signal, muddier causal story. If the ladder
  lights up, we can't cleanly say "training on failures worked" —
  we'd be mixing signal from training on failures AND training on
  general GSM8K.
- Rejected for first iteration.

**Option C (strategic sampling from train-split that matches failed
problems)**:
- Would require similarity scoring between test-split failures and
  train-split candidates. Operator-defined "similar". Larger
  machinery for a first-pass experiment.
- Rejected for first iteration.

**Option A (just the 200 failures)**:
- Clean causal story. The adapter is trained on exactly the
  problems the bare model failed. Phase 6's baseline-rerun measures
  "did the adapter learn these answers" (memorization). Phase 6's
  holdout measures "did the adapter learn the SKILL" (transfer).
  Clean two-signal design.
- Chosen as the first iteration.

If Option A fails to light up the holdout (H2 not met), TB-US-076
could pick up Option B or C.

## Mapping training signal to Phase 3 failure modes

Phase 3's baseline analysis identified four failure modes with
counts across the 200 bare-baseline failures:

| Mode | Count (bare baseline) | Training signal provided |
|---|---|---|
| FM1 abandoned question | 59 (29.5%) | Each training example is a self-contained Q+A pair ending in `#### N`. If the model learns to emit the pattern + stop, it won't drift to a new fictional Question block. |
| FM2 format drift | 25 (12.5%) | Every training example ends with `#### N`. Trained adapter should emit `#### N` reliably. |
| FM3/FM4 wrong number | 81 (40.5%) | Training on correct `<<arith>>`-annotated step-by-step reasoning teaches both the arithmetic patterns and the operation choices. This is the biggest signal and the biggest bucket. |
| FM5 truncated / format edge | 35 (17.5%) | Partial coverage — training on complete well-formatted answers encourages termination at `#### N`. LaTeX decoration + inference-config edge cases may need separate handling (follow-up). |

**Combined coverage**: 165/200 = **82.5%** of baseline failures
have an explicit training signal targeting them. The remaining
17.5% (FM5) is partially addressable; follow-up stories can tune
inference config if that bucket persists post-training.

## Pre-registered hyperparameters

From `study-design.md`'s "Training hyperparameters (pre-stated)"
section. No post-hoc adjustment.

| Hyperparameter | Value | Why |
|---|---|---|
| LoRA rank | 32 | Up from 16 (shipped v2 adapter); more capacity for failure-mode patterns |
| LoRA alpha | 64 | 2× rank, standard ratio |
| Learning rate | 2e-4 | Same as TB-US-057 |
| Epochs | 5 | Up from 3; targeted training on ~200 problems is small, more epochs help |
| Batch size | 4 | Same as TB-US-057 |
| Gradient accumulation | 4 | Same as TB-US-057 |
| Dropout | 0.05 | Light regularization |
| `max_train_samples` | 200 | All failures; no sampling-down |
| `max_eval_samples` | 50 | During-training eval on a subset; final eval is at n=200 via the harness |
| Target duration | ~45 min on RTX 3090 | 200 samples × 5 epochs with gradient_accumulation=4 ≈ 250 effective steps |

## Base model: Llama 3.1 8B *base* (not Instruct)

Pre-registered in `study-design.md`. Keeps the TB-US-057 baseline
narrative pure: "we trained everything from scratch". If H2 is
near-zero, TB-US-076 would retry with Instruct variant — a
pre-registered next step, not a post-hoc rationalization.

## Hypotheses (reiterated from study design)

| Hypothesis | Numeric threshold | Interpretation |
|---|---|---|
| H1 | Baseline accuracy post-training ≥ **50%** | We're training on exactly those 200. If training does anything, ≥50% should land. Close to memorization threshold. |
| H2 | Holdout accuracy post-training ≥ **10%** | Up from 0%. 200 unseen problems. Measures GENERALIZATION — is the adapter learning the skill or just memorizing. |
| H3 | Gap (H1 − H2) small = learning / large = memorization | ≤15 points = strong result; 15–40 = mixed; >40 = memorization-dominated |

## Registration (R13)

Training set gets registered on the live TB dev tree as
`training_set_versions.v4` on agent 3 (next version after the
shipped v3). Registration happens via the TB API with content_sha256
auto-computed from the file.

**Why v4 not v2**: the dev tree already has `training_set_versions.v3`
from TB-US-057 Phase A's seeder (the shipped math-example-v1.jsonl,
which v3 refers to in the DB due to AUTOINCREMENT drift). The new
failures-based training set is the NEXT version.

## Disjointness audit

Confirmed by `scripts/prep_math_failures_jsonl.py` at generation time:

- Training set (200) ⊂ GSM8K test split (seed=42, first 200
  shuffled) — same 200 as `math_eval_200.jsonl`
- Holdout (200) ⊂ GSM8K train split (seed=43, first 200 shuffled)
- Training ∩ Holdout = **∅** (strictly disjoint; GSM8K test and
  train splits are disjoint by construction)

**Implications**:
- Baseline rerun post-training (Phase 6 E1b): training set and
  baseline test are the SAME 200. In-sample measurement — expected
  high accuracy (H1).
- Holdout post-training (Phase 6 E_holdout): holdout is NEVER seen
  in training. Out-of-sample measurement — pure generalization
  check (H2).

## Scope cap

One training iteration. If H1/H2 outcomes point to a second
attempt (e.g., Option B scale-up, Instruct variant swap, larger
rank), TB-US-076 captures it. **This story does not loop.**
