## Design Notes

- **Why Jekyll (not Next.js / Astro / Hugo):** GitHub
  Pages has native Jekyll support without any build
  config. Lower friction, no deployment pipeline to
  maintain. The site is content-heavy, not app-like —
  SSG is right.
- **Why amber accent across both surfaces:** visual
  continuity between the marketing site and the app
  tells visitors "yes, you're in the right place" once
  installed.
- **Why Concepts page separate from Getting Started:**
  some visitors want to read concepts before deciding
  to install; others want to install first and look up
  concepts as they encounter them. Separate pages
  support both.
- **Why minimal SEO + no analytics default:** this is
  an OSS tool, not a product landing page. We're not
  running campaigns. Keep the surface clean.
- **Dual-surface pattern (README + Pages) is
  deliberate:** README stays short (2-min hook, repo
  default view); Pages has the room for diagrams,
  measurements, and narrative. Each surface earns its
  keep.

## Completion Notes (2026-10-24)

### Delivered

- **`docs/pages/_config.yml`** — Jekyll config: title, tagline, description, kramdown markdown with GFM input + rouge syntax highlighting, permalink pattern, defaults applying the `default` layout to all pages
- **`docs/pages/_layouts/default.html`** — single shared layout. Sticky header (brand + nav + GitHub button) + main content area + footer. CSS defines amber-accent variables matching TB-US-042 palette (`#CC785C` primary, `rgba(204,120,92,0.08)` tint). Mobile-responsive breakpoint at 640px. Jekyll `{{ page.url }}` logic drives nav-item active-state highlighting.
- **5 content pages** (~800 lines total):
  - **`index.md`** (Home) — hero card with pitch + two CTAs (Install / See it in action) + three feature cards (Staged progression / Explore an agent / Start your own) + Who it's for + What's inside
  - **`getting-started.md`** — 10-minute walkthrough: clone/venv → config → start → first login → see what you have → try shipped math-example
  - **`staged-progression.md`** — three-experiment demonstration (bare → +adapter → +RAG) with illustrative example outputs + honest expectation-setting that RAG may not help on GSM8K + "Reproduce or fork" section
  - **`concepts.md`** — Agent / Versioned component / Sweet Spot / Experiment / Two-tier architecture / Harness. Cross-links to the TB-US-NNN stories that define each concept
  - **`install.md`** — summary of repo INSTALL.md: prerequisites + Track A/B fork + first-boot side effects + first-login tour + troubleshooting + operational notes (one-run-at-a-time, auto-reap)
- **`docs/pages/README.md`** — operator-facing instructions for enabling GitHub Pages when the repo goes public (Settings → Pages → source = `/docs/pages` on main branch), plus notes on `baseurl` configuration for subpath vs root deployment, local-preview instructions, and content-ownership guidance
- **`.github/workflows/pages-build.yml`** — CI check: Ruby 3.3 + Jekyll 3.9.3 + plugins approximating GitHub Pages' production build. Builds the site on every PR touching `docs/pages/` or the workflow itself; smoke-checks that all 5 pages produce HTML. Fails the PR check if anything breaks

- **R5 diagrams:** The staged-progression page uses markdown tables for the three-experiment pin-down; prose for the architecture description. Didn't ship ASCII block diagrams duplicating TB-US-044. The links to the design docs cover readers who want the full architecture picture.
